# Celphonica v0.4

A browser instrument for landscape Android phones, played with two thumbs. Launch from App Lab or serve the repository and open `/small-apps/celphonica/` (a domain-root deployment also works). No runtime dependencies or build step. Serve over HTTP/HTTPS; ES modules do not load reliably from `file://`.

Touch a note to unlock audio. Hold for sound, release to stop, or slide between notes for discrete pitch changes. Multiple pointers can play chords, including two fingers on the same pitch. Sliding outside the notes stops that pointer; sliding back in starts it again. There is no sustain. Low notes are on the bottom row. Each row contains one cycle of the chosen scale from its root, without duplicating the next row's root. Sharp note names are used consistently (including enharmonic equivalents).

The landscape performance screen has three regions: left-thumb expression, a large central motion level, and the three-row note keyboard on the right. All notes are retained, with pitch and octave labels on separate lines. The square XY pad has a larger, fully visible marker; the volume slider has a console-style fader handle and responds to taps/drags across its full track area. Portrait shows a rotate-phone message instead of a playable keyboard. **Full screen** stays on the main screen and attempts landscape orientation lock where supported; failure leaves fullscreen usable with a rotate message. No system rotation setting is changed.

Open the gear to configure root, chromatic/major/natural minor/major pentatonic scale, sine/triangle/sawtooth sound, octave, expression mode, master volume, motion sensitivity, sensor enable/disable, and the separate motion audio mappings. Close with the **left-side ✕**, a tap outside, or Escape. The drawer scrolls on short screens. Opening settings stops held notes and blocks background playing. Octave buttons shift all three rows together; the starting root octave remains bounded to 1–6. Settings survive drawer closure and orientation changes for the current page session.

The header shows `Key: C maj | Note: C6`, using the actual root/scale and retaining the last pressed or slid-to note after release. Chords show up to three distinct notes plus a remaining count; their full names are in the readout's tooltip and accessible label. Releases do not collapse or erase the last played chord. Before the first note, the note field shows `—`.

The left XY pad maps horizontal position to filter brightness and vertical position to expression level. The **vertical volume slider** now controls expression level instead of brightness. Master volume in Settings remains an independent limit: output level is master volume × expression level. Switching modes retains the current brightness and level; the slider never changes filter cutoff or pitch. The controls retain their values after release but never sustain notes, and support simultaneous touches with the keyboard.

Enable sensors in Settings and grant access if requested. Separate **Pitch bend** and **Volume expression** switches both start **OFF** on a fresh page. When enabled, the bubble's horizontal coordinate bends ±2 semitones and its vertical coordinate multiplies manual expression by 0.85–1.15. Center targets original pitch and normal gain. Held voices change smoothly without restarting; disabled/lost sensors return safely to neutral. Each new note press captures neutral before the new voice starts, including chord fingers; sliding keeps the reference. Tap the visible circle to recenter manually. Sensor math, 45 ms smoothing and gravity fallback remain in place. See [MOTION.md](MOTION.md) and [MOTION_AUDIO.md](MOTION_AUDIO.md) for mappings, safety and physical phone tests.

`music.js` defines scale intervals and pitch labels. `instrument.js` owns DOM, pointer capture, hit testing, cancellation and independent manual/motion mapping. `synth.js` owns the interactive AudioContext, per-pointer oscillators, 1 ms attack / 35 ms release, lowpass filter, master gain, and a memoryless overload guard. There is no compressor, look-ahead or added oversampling. Manual `setExpression` and motion `setMotion` are separate APIs. Oscillators and envelopes disconnect after release. Backgrounding, blur, page exit, and resize clear held notes; late audio unlock promises cannot restart released pointers. Settings, expression, and fullscreen pointer gestures can prepare audio silently before the first note.

## Verification

Run `python celphonica/test-browser.py` from the repository root with development-only Python Playwright and Chromium installed. It exercises real browser audio nodes, delayed unlock/release, mouse dragging, Android-style CDP multitouch, cancellation, settings, expressions, viewport layouts, and navigation at `/` and `/small-apps/`. Screenshots are written to `/tmp/celphonica-desktop.png`, `/tmp/celphonica-landscape.png`, and `/tmp/celphonica-portrait.png`. Run the existing regression commands in `tests/README.md` and each app's README as well.

Run `python celphonica/test-latency.py` for synchronous pointer-to-start assertions and offline audio onset measurements. It checks production Synth code at 44.1/48 kHz against the v0.1 topology and isolated filter, attack, and compressor paths. Results go to `/tmp/celphonica-latency.json`. See [LATENCY.md](LATENCY.md) for the comparison, measured results, tradeoffs, and physical testing procedure.

Run `python celphonica/test-motion.py` for simulated orientation/gravity streams, permission and unavailable-sensor handling, reference capture, smoothing, sensitivity, screen rotation, circular bounds, simultaneous touch/audio/XY behavior, and portrait/landscape layouts. A landscape screenshot is written to `/tmp/celphonica-motion-844.png`.

Run `python celphonica/test-performance.py` for v0.3 geometry, readable/reachable notes, drawer dismissal/focus/touch scrolling, simultaneous touch and volume, portrait transitions, and fullscreen/landscape-lock fallback checks. See [PERFORMANCE.md](PERFORMANCE.md) for supported viewport tests and physical phone follow-up.

Run `python celphonica/test-v04.py` for real simulated pad/fader touches, square pad geometry, non-overlapping settings controls, retained readout/chords, live motion modulation without retrigger, safe neutral returns, sample-level bend/volume renders, and output overload bounds. Screenshots are written to `/tmp/celphonica-v04-pad.png`, `/tmp/celphonica-v04-fader.png`, and `/tmp/celphonica-v04-settings.png`.

Physical Android testing remains necessary: speaker audibility and distortion, perceived latency and click suppression, thumb reach and fatigue (especially 12-column chromatic mode), real multitouch/palm behavior, browser edge gestures, full screen and browser chrome, interruptions/audio focus, and recovery after lock/unlock. Browser automation verifies audio graph behavior; it cannot establish perceived sound quality or hardware ergonomics.

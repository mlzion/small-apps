# ChordMidi v0.3

A static, portrait-first chord progression composer. Launch `chordmidi/` from App Lab, or serve this repository with any static server. No build, account, CDN or runtime dependencies. All paths are relative and work at `/chordmidi/` and GitHub Pages `/small-apps/chordmidi/`.

## Compose

Six three-position thumbwheels select key, major/natural minor, scale degree, chord quality, inversion and octave. Swipe vertically, drag with a mouse, use a mouse wheel, tap adjacent options, or focus a wheel and use Up/Down/Home/End. Two-choice mode shows each available option once; a root-only inversion wheel shows Root in the center with blank neighbors. The center is always selected. `◇` marks diatonic triads and sevenths; the third dyad is also derived from the scale. Alternative major/minor/diminished/augmented, power, suspended, sixth and seventh qualities remain available on every degree. Spellings follow scale letters, including E♯, C♭ and double accidentals where necessary.

The **Octave 1–8** dyad plays exactly the scale-degree root and the same note 12 semitones higher, with only root-position inversion. Both RH and LH support it; its note readout includes both octave numbers (for example C4–C5, or B♯4–B♯5). It works with Drop, placement, tap preview, playback, JSON and MIDI like the other qualities.

Choose **RH** or **LH** above the builder to retain independent degree, quality, inversion and octave settings. Key and mode are shared. Octave 4 starts the tonic in MIDI register C4–B4 (C4 = MIDI 60); degrees above the tonic can cross into the next register, and inversions lift the lowest voices by an octave. The readout gives full quality, inversion, octave, spelled notes and exact MIDI pitches. **Drop** auditions the current builder chord without placing it.

Key and Mode wheels are always **song settings**. Selecting a block never changes them. A block created in another key/mode restores an independent builder context; the existing hint identifies both, for example **Builder D Minor · Song C Major**. Interval names, quality, inversion, register, Drop and new placement follow that builder context. Switching RH/LH keeps each hand’s current context. The original event’s stored pitches remain authoritative.

For an imported/custom voicing that cannot be generated by its wheel template, the readout explicitly says **stored voicing** and **wheels show its template**. Drop and untouched placement use the exact stored pitches. Editing a chord wheel clears that stored preview and creates a new chord from the shown template in its original context; it never overwrites the selected event. Selecting passing notes likewise restores a local scale/source context without changing the song; source-option labels identify a foreign context. A note that cannot be represented by its source options appears as a temporary **Stored** option.

A deliberate Key/Mode wheel edit retains the existing behavior: builders return to the song context, while existing arranged events are neither transposed nor cleared. No arrangement-level transpose/clear prompts or Major/Minor conversion workflow are added in v0.3.

- Tap an empty eighth-note pad to place a chord or passing note. Desktop: drag horizontally from the pad to extend its duration. Touch: **hold an empty pad for 260 ms, then drag**; a normal swipe scrolls the timeline.
- Short-tap a RH or LH chord to select it, restore its original lane-builder context and settings without changing the song Key/Mode, and audition its **stored MIDI pitches** with the current instrument. A second tap cuts the previous preview with a short de-click fade. Auditioning does not start playback, seek the transport or change the block. Passing-note selection remains silent. Selecting never changes stored pitches. Drag its right edge to resize. Hold any part of the event for 650 ms to delete; moving cancels deletion.
- **Copy** snapshots selected pitches, settings and duration. **Paste** arms placement; tap an empty pad in either chord lane, or the passing lane for a copied note. Paste again cancels. Lengths that exceed the grid are refused. A chord cannot be pasted into the single-note lane.
- Keyboard: Enter/Space places or selects, Delete removes a focused event, Shift+Left/Right resizes it.
- Passing Notes offers scale notes or current RH chord tones and its own octave. Events always hold a single actual pitch.
- Choose 1–8 bars and 2/4, 3/4, 4/4 or 6/8. Length is in eighths: 4, 6, 8 or 6 per bar. Shortening is refused if it would cut off events; resize/delete those events first. Existing onsets retain their eighth-note offsets when changing meter.

To replace a chord, select it, adjust the wheels and audition with Drop, delete the original, then place the replacement. Wheel changes and Drop never automatically replace or overwrite a block.

Each event stores actual pitches, start, duration and builder metadata. Subsequent builder changes never transpose placed events. Overlaps are supported; same-pitch overlaps within a lane sound/export as a continuous held note, while adjacent events retrigger. RH and LH use independent MIDI channels.

## Audio and transport

All three lanes and Drop share one preview instrument. The main dropdown contains only the instruments enabled in **Setup → Instruments**, with 25 enabled on first launch. The library offers 96 instruments in 12 expandable General MIDI categories. The complete bundled **TimGM6mb SF2** still contains all 128 bank-zero presets and is unchanged. The approximately 6 MB bank loads on the first Play/Drop gesture and is then cached in memory; the first sound can take a moment. No network access is needed beyond fetching the app's own static files.

### Instrument library

Expand **Setup → Instruments**, then a category, to check or uncheck sounds. Changes update the main dropdown immediately. If the active instrument is unchecked, the preview switches to the first enabled program in GM order; all chord pitches, voicings and arrangement data remain unchanged. At least one instrument must stay enabled. The enabled count and category counts show the current selection; **Restore Defaults** restores exactly the original 25.

Labels use standard GM names, independently of the SF2's internal names.

Basses (33–40), Synth Leads (81–88), Synth Effects (97–104), and Sound Effects (121–128) are excluded from Setup to suit chord progression composing, not because of any limitation on playing simultaneous notes. The soundfont and polyphonic playback engine retain the complete bank.

The checklist is an app-wide preference in `app-lab-chordmidi-instruments-v1` localStorage. It persists across New/Load Project and browser sessions and is never included in project JSON. If storage is unavailable, changes still work for the current session and Setup reports the problem. Categories and the modal scroll independently on narrow portrait screens; controls use 44 px touch rows.

DruMidi was reviewed before implementation: `core.js` is a browser/Node model, `audio.js` uses native Web Audio sources with a 25 ms pump and 120 ms lookahead, `app.js` supplies autosave/JSON workflows, and its MIDI writer emits sorted delta-time events. Its browser playback uses decoded MP3 percussion samples; its standalone SF2 has a drum preset only. ChordMidi follows these working architecture and UI conventions with a separate melodic SF2 reader. No DruMidi files or assets are changed.

The native SF2 reader supports preset/instrument global/local zones, key and velocity ranges, sample offsets and loops, tuning, attenuation, pan and volume ADSR. Polyphonic sources have scheduled releases and note-offs. A master compressor provides headroom. It is a focused sample player for this bundled bank, not a complete SoundFont synthesizer: SF2 filter/modulator effects, chorus and reverb are not implemented, and user-supplied SF2 files are not supported. Sounds can differ from a full FluidSynth renderer. Pitches outside an acoustic preset’s natural sample range use its nearest zone, transposed to the requested pitch.

The fixed bottom transport offers return to start, Stop, Play/Pause, Loop, 30–300 BPM and metronome. Instrument selection stays directly above it; scroll the page on shorter displays to reach all editing controls. Audio time drives the cursor and all lanes. Pause silences voices and resumes held notes at the saved position. Stop/return/new/load/edit cancel scheduled sources. Backgrounding the page stops playback to avoid a burst of stale notes. 6/8 uses dotted-quarter metronome beats; other meters use quarter notes.

### Playback synchronization and previews

The scheduler uses `AudioContext.currentTime` with its existing 25 ms pump, 120 ms lookahead and a shared 40 ms scheduling lead at Play/resume. Lookahead queues sources; it does not advance the playhead. Chords, passing notes and metronome keep the same absolute source times, tempo and note lengths. Resumed held notes share one captured start time.

The playhead maps `getOutputTimestamp()`'s audio/performance clock pair to the current monotonic time to observe samples reaching the output rather than samples being rendered ahead. When that API is missing, invalid or throws, the fallback subtracts the browser's reported `baseLatency` and `outputLatency`. The two approaches are alternatives, avoiding double-counting device latency. No manually guessed audio/visual delay is applied.

The master `DynamicsCompressorNode` adds its own graph delay. On first audio initialization, an offline impulse is rendered through an equivalent compressor at the live context's sample rate; the first nonzero sample measures this delay. The playhead accounts for that measurement separately. Chromium in this environment measured about **5.986 ms**; that number is an observed test result, not a hardcoded correction. If offline rendering is unavailable or fails, playback works without guessing at the unmeasured graph delay.

In v0.2, each raw timestamp pair was directly extrapolated into cursor position. Driver estimate corrections could move that estimate backward even as audio kept playing forward; auto-scrolling could then react to the false reversal. v0.3 instead tracks **output latency relative to the monotonic audio render clock**. A five-observation median rejects timestamp spikes. Phase correction uses the measured observation cadence and limits latency slew to one eighth of audio-clock advance, so the presentation clock moves at 7/8–9/8 of render-clock speed while correcting. There is no extra fixed offset or maximum-previous-cursor clamp. Sustained latency changes converge to the new observed offset instead of accumulating drift.

Every animation frame derives position from absolute render time minus this stabilized latency and the scheduling anchor. The device-latency model is independent of transport position: loop modulo, a new Play/resume anchor, rewind, Stop and tempo restart still allow their legitimate backward position changes. Chord leading edges now share the grid/bar origin. The viewport follows in small increments as the cursor reaches its right margin; a loop resets to the start. Pause freezes the estimated audible position and resume holds it until its new start reaches output. Natural playback completion waits for the audible final boundary. Stop resets immediately, and tempo edits retain the existing Stop/restart workflow with a fresh anchor.

Chord previews use a separate voice group from arrangement playback. A tap plays a 0.8-second held chord followed by the instrument's normal release; Drop retains its 1.2-second hold. Preloaded samples use one render quantum of scheduling headroom for a responsive onset. New previews cancel earlier preview voices with a 5 ms de-click fade, without cutting arrangement voices or moving the cursor. Rapid taps during the initial SF2 download keep only the latest request. Stop, Pause, Play, edits and backgrounding cancel obsolete previews. Movement, resizing, scrolling, pointer cancellation and long-press deletion do not trigger previews; queued input timestamps also protect holds when the main thread delays the deletion timer.

A real output-device latency change is followed gradually; phase alignment can temporarily be less precise during reacquisition. These are software clock estimates, not a measurement of sound leaving a physical speaker. Bluetooth/device buffers, inaccurate driver timestamps, missing latency APIs and display/compositor frame latency can leave residual offsets. SF2 instruments' intentional sample/attack envelopes also affect perceived attack and are preserved. Samples already handed to an output device cannot be recalled instantly on Stop/Pause. Physical Android speaker/Bluetooth checks are still required; no arbitrary correction is added to hide those limitations.

## Projects and MIDI

v0.3 preserves chord generation (including diatonic Triad ◇ and Octave 1–8), stored event pitches and MIDI export. Existing version-1 JSON projects still load. Optional builder/passing `context` fields retain the original `{key, mode}` separately from song settings; optional `voicing` fields retain exact stored `{pitches, label}` when the template cannot represent them. These current editor settings survive Save/Load/reload. New events record their own original key/mode and actual pitches; selecting or editing a builder never mutates an existing event.

The top-right **Setup** gear contains project name, New, Save, Load, Export MIDI and the Instruments library. Autosave uses a separate `app-lab-chordmidi-v1` localStorage key. **Save Project** downloads a complete JSON backup; Load validates the format, settings, event bounds and MIDI pitches before asking to replace the project. New also asks before replacement. Invalid imports leave the current project intact. Storage/audio failures are reported with recovery instructions.

Project JSON saves the preview's standard GM name as `instrumentName` and its 0-based GM number as `program`, for example `{"instrumentName":"Acoustic Grand Piano","program":0}`. Load restores both and validates their correspondence. If the loaded instrument is unchecked (even a program excluded from Setup), a temporary **Project preview** entry appears in the main dropdown so it plays as saved. This does not change the app-wide checklist. Unrelated checklist changes keep the imported sound; explicitly disabling it, restoring defaults or choosing another instrument removes the temporary entry when no longer needed. New projects use an enabled instrument. Earlier unreleased JSON without the instrument name is not migrated.

**Export MIDI** downloads SMF format 1 at 480 PPQ with exactly three named tracks: RH Chords, LH Chords, Passing Notes, on channels 1–3. No track contains MIDI Program Change messages; the DAW chooses its own instruments. Near the beginning of track 1, a MIDI text meta event (`FF 01`) records `Preview instrument: <standard GM name>`, for example `Preview instrument: Acoustic Grand Piano`. Track 1 also includes tempo and time signature. Each eighth is 240 ticks. Inversions/octaves are already encoded as pitches; ends are exact and note-offs precede same-tick retriggers. Same-pitch overlaps in a lane are unioned to avoid premature note-offs in DAWs. Arrangement overlaps across lanes remain independent. Metronome is a playback aid and is not exported.

```sh
python drumidi/test-browser.py
```

Set `CHROMIUM_PATH` if Chromium is elsewhere. Browser checks route an HTTPS test origin to local files and load the real soundfont; they do not use a mock audio bank. Screenshots go to `/tmp/chordmidi-*.png`.

The model suite checks Octave 1–8 across every key, mode, degree, hand and supported octave, rejects invalid inversions and checks spelled octave labels, pitch bounds, JSON and parsed MIDI. It also checks all 12 keys, both modes, all qualities/degrees/inversions at three registers, explicit pitch and spelling examples, JSON validation/roundtrips, meter lengths and an independent MIDI decoder checking three tracks, preview text metadata, absence of Program Changes, channels, overlapping pitches, onsets and note durations. Browser checks exercise actual CDP touch gestures, mouse and keyboard, editing/scroll cancellation, independent lanes and fixed pitches, all meters, 8 bars, every GM preset's sample decoding, actual audio-clock scheduling, polyphony, passing notes, note-off/stop, pause/resume, looping/metronome, JSON/MIDI downloads, malformed imports, storage/audio failures, fullscreen, six viewport sizes and both hosting roots. The instrument suites independently verify the 12 category ranges, all 96 eligible programs, all 25 default GM names/numbers, exclusions, checkbox/dropdown synchronization, fallback and last-enabled protection, reload/new-project/session persistence, Restore Defaults, hidden eligible/excluded project previews, real selected-instrument SF2 playback, JSON name/program round trips and parsed three-track MIDI with preview text and no Program Changes. The Setup accordion is checked at 320, 360, 393 and 412 px widths. Gallery checks preserve the existing apps and navigation.

The synchronization suite adds deterministic checks at 30/60/120/137/300 BPM, all meters, eight bars and three loop cycles with independent simulated render/output clocks. It covers timestamp extrapolation, latency fallbacks, measured graph delay, audible pause/resume/end, tempo restart and latest-wins preview cancellation/voice isolation. Browser comparisons allow display-frame granularity; they do not certify hardware latency.

The v0.3 stability suite checks 575,672 assertions across five tempos, all meters, eight bars and three loops. It reproduces 57,354 raw timestamp reversals without a stabilized reversal, including fallback jitter, isolated spikes, same-quantum corrections, sustained latency changes and transport repositioning.
